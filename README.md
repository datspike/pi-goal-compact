# pi-goal-compact

Расширение [Pi](https://github.com/badlogic/pi-mono) для долгой работы агента. Оно ведёт работу к цели через много окон контекста и сжимает контекст так, чтобы по дороге не терялось, чего на самом деле хотел владелец.

Одно расширение заменяет два прежних: [pi-codex-goal](https://github.com/datspike/pi-codex-goal) (долгие цели) и [context-compaction](https://github.com/datspike/context-compaction) (окно контекста и сводки сжатия). Сессии, начатые с ними, открываются и продолжаются без переделки.

> **Состояние.** Расширение работает и проверено, но в npm не опубликовано. Версия `0.0.0`, ставится из локальной копии. Append-сжатие с сохранением кэша провайдера из `context-compaction` ещё не перенесено: пока сжатие всегда делается обычной сводкой.

## Зачем это нужно

Долгая работа агента живёт дольше одного окна контекста. При сжатии история заменяется пересказом. После нескольких сжатий агент работает уже по пересказу пересказа: исходных слов владельца в окне нет. Работа не останавливается, она понемногу уходит в сторону. Цель закрывается, когда сходятся счётчики, а не когда сделано то, о чём просили.

Ведение цели и сжатие контекста решают одну задачу — довести работу до того, о чём договорились. Поэтому здесь это одно расширение. Две отдельные части раньше согласовывали между собой, что модель увидит в начале нового окна. Теперь это решается в одном месте.

## Что получает владелец

**Договорённость в каждом окне.** Ставя цель, агент записывает договорённость в трёх частях: чего хочет владелец, что агент решает сам без подтверждения и когда работа готова. После каждого сжатия договорённость стоит в начале окна сразу после сводки, поэтому модель видит её, а не только свой пересказ.

**«Решаю сам» — отдельным списком.** Допущения и выборы, которые агент сделал без владельца, не растворяются в тексте цели. Подтвердить или отклонить пункт может только владелец.

**Закрытие с вопросом.** Первая попытка закрыть цель возвращает агенту договорённость. Он должен ответить своими словами, чем сделанное отвечает каждому требованию владельца. Счётчики и зелёные проверки подтверждают учёт, а не результат.

**Сводка, которая держит замысел.** Сводка сжатия сохраняет дословные слова владельца о цели, статус каждого решения («принято», «открыто», «отклонено»), все связанные объекты (MR, ветки, окружения), источник каждого шага и точные пути. Служебные инструкции цели в сводку не попадают.

**Работа без лишних касаний.** Пока цель активна и агент простаивает, расширение само продолжает работу скрытым сообщением. Оно учитывает время и токены, ставит цель на паузу по Esc, переживает ошибки провайдера, переполнение окна, перезапуск и `/reload`. Когда агент ждёт ответа владельца, продолжений нет.

В native fork дочернего агента родительская Goal остаётся историей: она не запускает ход и не управляет его завершением. Ребёнок может завести собственную цель; она сохраняется после перезапуска и `/reload`. Интерактивные форки продолжают цель как прежде.

**Управляемое окно.** Режимы окна контекста: экономный по умолчанию, увеличенный на одно сжатие или на весь разговор. В нижней строке видно заполнение окна, порог сжатия и состояние цели.

## Установка

Нужны Pi 1.5 и Node.js 22.19 или новее.

```sh
git clone <адрес репозитория> pi-goal-compact
cd pi-goal-compact
npm install --omit=dev
pi install "$PWD"
```

Если стоят `pi-codex-goal` и `context-compaction`, уберите их из `settings.json` Pi перед установкой. Вместе с новым расширением они дублируют инструменты и команды. Откат — вернуть две прежние строки и убрать новую.

## Как пользоваться

Скажите агенту, что хотите поставить цель, и опишите результат. Прежде чем вызвать `create_goal`, агент одним пакетом спрашивает обо всём, что меняет охват, устройство или приёмку и ещё не решено. Если вы попросили работать без вопросов, он не спрашивает, а записывает свои допущения в «Решаю сам».

Дальше агент работает сам. Он публикует короткие отчёты о сдвигах, записывает решения и отложенные проблемы. Закрывает цель только после сверки с договорённостью. Документ цели лежит в `.pi/goal-compact/<goalId>/GOAL.md` внутри проекта. Он создаётся заново из данных цели и только для чтения.

### Команды

| Команда | Что делает |
|---|---|
| `/gs` | Короткий статус цели |
| `/gw` | Обзор работы: план, следующий шаг, ссылка на документ цели |
| `/gp` | Поставить активную цель на паузу |
| `/gr` | Снять цель с паузы без нового запроса к модели |
| `/gc` | Очистить текущую цель |
| `/context [status\|economy\|long-once\|long-chat\|off]` | Показать или сменить режим окна контекста |

### Инструменты модели

| Инструмент | Назначение |
|---|---|
| `create_goal` | Поставить цель с договорённостью и списком «Решаю сам» |
| `get_goal` | Прочитать цель: полностью, кратко или историю |
| `update_goal_work` | Обновить план работы |
| `report_goal_progress` | Опубликовать отчёт о сдвиге для владельца |
| `record_goal_note` | Записать решение, пункт «Решаю сам» или отложенную проблему |
| `amend_goal` | Дополнить договорённость после реплики владельца |
| `resume_goal` | Снять цель с паузы по слову владельца |
| `update_goal` | Закрыть цель |
| `load_goal_language_guide` | Показать, как исправить отклонённый текст отчёта |
| `checkpoint_compact_continue` | Сохранить контрольную точку, сжать контекст и продолжить ту же задачу |

### Смена модели после сжатия

`/model-next` открывает выбор модели для ближайшего успешного сжатия. `/model-next-now` просит сжатие и переключение после текущего хода, не обрывая выполняемый инструмент. Обе команды работают с целью и без неё: без аргумента открывают поиск, точное имя `provider/model` выбирает модель сразу, неполное имя открывает поиск с этим текстом. Доступны автодополнение и необязательный `--thinking medium` с другим поддержанным уровнем.

`/model-next status` показывает ожидающую передачу, `/model-next cancel` отменяет её. Пока модель уже применяется, отмена не принимается: сначала нужно дождаться результата. Ожидание сохраняется при `/reload` и перезапуске; переход в другую ветку, сессию или ручной выбор модели отменяет его.

Сводку пишет прежняя модель. Новая применяется только после сохранения сжатия; пауза цели и ожидание владельца сохраняются. Из простоя без активной задачи новая работа не начинается. Ошибка останавливает передачу с уведомлением: отмените её или повторите выбор. Вместимость меньшего окна проверяется оценкой сводки, свежего хвоста, системных инструкций и инструментов; это оценка, а не точный токенизатор провайдера. Системные инструкции и свежий хвост остаются во входе новой модели; перенос кэша не обещается.

### Режимы окна

- `economy` — по умолчанию: окно не больше 272 тысяч токенов, Pi начинает сжатие около 256 тысяч.
- `long-once` — до 372 тысяч до следующего успешного сжатия, затем снова `economy`.
- `long-chat` — до 600 тысяч на весь разговор.
- `off` — окно из реестра моделей без ограничения расширения.

Увеличенные режимы включаются, только если запись модели в реестре Pi объявляет такое окно и ценовой уровень для него. Расширение не меняет `models.json`: окно переопределяется только для текущей сессии.

## Настройки

Язык и окно сжатия задаются в `settings.json` Pi:

```json
{
  "contextCompaction": {
    "language": "ru",
    "compactCapabilities": []
  }
}
```

- `language` — `ru` (по умолчанию) или `en`: язык промптов цели, сводок и уведомлений. Прежний ключ `summaryLanguage` тоже читается.
- `compactCapabilities` — проверенные окна служебного запроса сводки для точных маршрутов провайдера. Это нужно, если маршрут на деле принимает больше, чем объявлено в реестре.
- `appendCompaction` читается для совместимости, но пока ни на что не влияет.

Поведение цели настраивается в `goal-reports.json`: глобально в каталоге агента Pi и для проекта в `.pi/goal-reports.json`. Проектный файл перекрывает глобальный только в названных полях, выключатели — по одному.

```json
{
  "afterActiveSeconds": 500,
  "afterAssistantTurns": 30,
  "maxHiddenContinuations": 0,
  "features": {
    "agreementInWindow": true,
    "completionReturn": true,
    "selfDecidedList": true,
    "askBeforeGoal": true,
    "singleFactOwner": true,
    "ownerRepliesWithoutGoal": true,
    "amendNeedsOwner": true
  }
}
```

`afterActiveSeconds` и `afterAssistantTurns` задают, как часто агент публикует отчёт. `maxHiddenContinuations` ограничивает скрытые продолжения подряд без сообщения владельца; `0` — без предела.

Выключатели в `features` возвращают поведение прежней пары расширений по одной доработке. Так можно сравнить или откатить одну доработку, не трогая остальные.

| Выключатель | Что включает |
|---|---|
| `agreementInWindow` | Договорённость в начале окна сразу после сводки |
| `completionReturn` | Первая попытка закрытия возвращает договорённость |
| `selfDecidedList` | Список «Решаю сам»; состояние пункта меняет только владелец |
| `askBeforeGoal` | Правило задать вопросы до постановки цели |
| `singleFactOwner` | Каждый факт живёт в одном месте: сводка не пересказывает цель, продолжение не повторяет её |
| `ownerRepliesWithoutGoal` | Без цели после сводки стоят последние реплики владельца дословно |
| `amendNeedsOwner` | Правка договорённости принимается только после настоящей реплики владельца |

Договорённость в `create_goal` нужна всегда, выключатели этого не отменяют.

## Переход с прежних расширений

- Цели, отчёты и записи `pi-codex-goal`, режим окна и карточки `context-compaction` в журналах сессий читаются под прежними именами. Журналы не переписываются.
- Документы целей, начатых прежним расширением, дописываются в прежнем каталоге `.pi/pohuy-goal/`. Новые цели пишутся в `.pi/goal-compact/`.
- У цели прежней пары нет договорённости. В окне вместо неё показывается прежний текст цели.
- Перед сжатием служебные продолжения цели убираются из входа сводки, в том числе записанные прежним расширением. Самые ранние формулировки продолжений не узнаёт ни новая версия, ни прежняя. В проверенных сводках модель их не переносила.

## Ограничения

- Append-сжатие с сохранением кэша провайдера ещё не перенесено.
- Договорённость пишет модель своими словами. Расширение хранит её без правок, но точность пересказа зависит от модели.
- С `language: "en"` инструкция сводки не задаёт язык явно: на русской истории сводка выйдет по-русски.
- Команда `compact` через RPC посреди хода обрывает ход, и цель встаёт на паузу. Ручной `/compact` в простое так не делает.

## Как это проверено

- `npm run verify` одной командой: типы, слои и неиспользуемый код, 849 тестов, проверка, что в дереве нет приватных путей, и модели TLA+.
- Две модели TLA+ в `formal/`: продолжение с удержанием и договорённость с закрытием. Для каждого свойства есть намеренная поломка, на которой проверка падает. Подход — в [решении 0008](docs/adr/0008-formalnaya-proverka.md).
- Дымовые прогоны на настоящем Pi без сети: ответ на вопрос переживает сжатие и перезапуск, сессия прежней пары продолжается новой версией, правка цели без реплики владельца отклоняется.
- Сценарии на модели, по которым раньше ловили сбои: петли проверок вместо закрытия, потеря четырёх MR после сжатия, принятое без согласия решение, закрытие по счётчикам вместо результата. Новая версия проходит их не хуже прежней пары.
