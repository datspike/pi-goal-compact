# 0008. Модели TLA+ — чертёж ядра, намеренные поломки входят в проверку

## Контекст

Главный источник тонких ошибок — порядок событий: сжатие, конец хода, обрыв, повтор, ответ сабагента, реплика владельца. Тест проверяет порядок, который кто-то догадался написать; TLC перебирает все порядки в заданных границах.

## Решение

Две модели в `formal/`: продолжение и удержание (П1–П6), договорённость и закрытие (П7–П9). Модель пишется раньше кода и служит чертежом ядра. Каждое свойство показано падающим на правдоподобной поломке; поломки выбираются параметром `Bug` и входят в `npm run check:formal` наравне с исправной моделью. Контрпример пересказывается цепочкой действий.

TLC закреплён: `tla2tools.jar` релиза v1.8.0, контрольная сумма сверяется при каждом запуске.

## Альтернативы

- **Полный конвейер Specula** со снятием трасс с настоящего кода. Отклонено: цена 34–53 $ на систему, из неё 41% — обвязка.
- **Только тесты.** Отклонено: история прежних расширений — это тесты, написанные после найденного случая.

## Последствия

- Изменение правила ядра требует изменения модели в том же коммите.
- Проверке нужна Java.

## Не входит

Поведение модели-агента — поймёт ли она договорённость — проверяется сценариями, не моделями.

## Проверка

`npm run check:formal`: 2 исправные модели и 12 поломок.

## Статус

Принято.
