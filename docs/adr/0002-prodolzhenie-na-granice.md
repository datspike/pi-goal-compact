# 0002. Продолжение решается на границе `agent_before_settle`, пути из простоя идут через билет с эпохой

## Контекст

Прежнее расширение цели продолжало работу скрытым сообщением в очередь Pi после конца прогона. Между постановкой сообщения и его доставкой могли случиться реплика владельца, обрыв, сжатие, смена ветки или закрытие цели. Отсюда весь класс «устаревшее продолжение в очереди»: таймеры повторной проверки, отмена прогона из `before_agent_start`, переписывание контекста.

В Pi 1.5 есть граница `agent_before_settle`: последняя точка перед простоем, где расширение может дописать записи и попросить ровно один следующий запрос модели (`continue: true`). Pi сам отменяет такое продолжение при обрыве и сам объединяет его с уже стоящими в очереди сообщениями.

## Решение

Обычное продолжение цели — ответ ядра на событие «конец прогона» на границе `agent_before_settle`: скрытое сообщение продолжения записью `custom_message` и `continue: true`. Очереди и таймера для него нет.

Работа из простоя начинается в четырёх случаях: после сжатия по запросу агента (решение 0003), после паузы перед повтором при ошибке провайдера, по завершении фонового сабагента и по команде возобновления. В этих случаях ядро кладёт в очередь Pi **билет** — скрытое сообщение с номером эпохи. Эпоха растёт на каждой реплике владельца, смене ветки или сессии, создании и очистке цели. При доставке билет сверяется с текущей эпохой и состоянием цели. Негодный билет в простое прерывает прогон до запроса к модели; билет, влившийся в чужой прогон, при сборке окна заменяется пустой пометкой.

Свежий билет в очереди бывает только один.

## Альтернативы

- **Продолжение через очередь, как раньше.** Отклонено: сохраняет весь класс устаревших сообщений.
- **Сжатие с продолжением целиком на границе — черновик записи `compaction`.** Отклонено решением 0003.
- **Продолжение из `agent_settled` через `sendMessage`.** Отклонено: это та же очередь, только позже.

## Последствия

- Защита от устаревшего продолжения сводится к сверке билета в одном месте.
- Прерывание своего негодного билета не должно ставить цель на паузу, как обрыв владельцем: ядро отличает свой отказ от `Escape`.
- Остановка активной цели без ожидания, сжатия, сабагента и паузы перед повтором всегда сопровождается уведомлением владельцу (свойство П6).

## Не входит

Повтор при ошибке провайдера делает Pi и PiRetry. Ядро решает только, продолжать ли цель после их итога.

## Проверка

Модель `formal/Continuation.tla`, свойства П1–П6. Поломки `noDedupe`, `noHoldCheck`, `completeRuns`, `noWriteGuard`, `noFreshGuard`, `noNotice`, `noGoalCheckOnTicket` в `npm run check:formal`.

## Статус

Принято.
