# 0016. Закрытие с текстом проверки

## Контекст

По решению 0005 закрытие идёт в два шага, и у второго шага есть условие — отчёт `verifying` для той же пары «редакция договорённости, версия плана». На практике закрытие стоило трёх-четырёх вызовов. Модель читала `get_goal(view=full)`, публиковала `report_goal_progress(status=verifying)` и дважды вызывала `update_goal(complete)`. Отчёт и первая попытка отвечают на один вопрос: чем сделанное отвечает каждому пункту «Готово, когда».

## Решение

`update_goal` принимает необязательный `verification` — текст проверки. Если цель не закрыта, текст записывается обычным отчётом `verifying` для текущих договорённости и плана. Запись идёт до сравнения версий, тем же путём, что `report_goal_progress`.

Два шага решения 0005 не меняются:

- первая попытка при новой паре версий возвращает договорённость, даже если текст проверки пришёл в ней же; ответ сообщает, что проверка записана;
- если текста не было и свежего отчёта нет, ответ первой попытки просит передать `verification` во второй;
- вторая попытка при той же паре закрывает цель, если отчёт `verifying` для этой пары есть — из прежнего `report_goal_progress` или из `verification` любой попытки;
- любая правка договорённости или плана снова обнуляет оба условия.

Обычное закрытие — два вызова `update_goal`. Цель без отчётов и плана по-прежнему закрывается без `verifying`.

## Альтернативы

- **Закрывать одним вызовом, если есть текст проверки.** Отклонено: возврат договорённости в первой попытке — то, что по решению 0005 вернуло модель к работе. Поломка `verifyOnly` в модели показывает закрытие без сверки.
- **Убрать требование отчёта `verifying`.** Отклонено: без текста проверки вторая попытка ничем не подтверждает результат.

## Последствия

- Закрытие — два вызова вместо трёх-четырёх.
- `report_goal_progress(status=verifying)` остаётся рабочим путём; прежние сессии закрываются как раньше.
- Записи журнала прежние: текст проверки — обычное событие отчёта.

## Не входит

Смысл текста проверки расширение не судит.
