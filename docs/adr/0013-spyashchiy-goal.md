# 0013. Без цели модель видит один `create_goal`

## Контекст

Расширение объявляло модели все свои инструменты в каждом запросе, даже в сессии без цели. Схемы и описания инструментов Goal занимали около 17 тысяч знаков, правила в системном промпте — ещё около 6 тысяч. Большинство сессий цели не ставят, а платят за неё в каждом запросе. Владелец ставит цель для долгой работы и не хочет заметного оверхеда там, где она не нужна.

## Решение

Без открытой цели модели объявлен один инструмент Goal — `create_goal`. Остальные регистрируются с `defaultActive: false`:

- `resume_goal`;
- `get_goal`;
- `update_goal_work`;
- `amend_goal`;
- `record_goal_note`;
- `report_goal_progress`;
- `update_goal`.

Расширение включает их через `pi.setActiveTools`, когда цель в работе, на паузе или с исчерпанным бюджетом. Набор меняется только для своих имён, чужие инструменты остаются как были.

Pi сам хранит активный набор в журнале и восстанавливает его при открытии сессии и смене ветки. Расширение только сверяет набор с состоянием цели.

Добавить инструменты можно сразу: после `create_goal`, перед стартом прогона и после каждого вызова инструмента. Снять их можно только на границах, где окно собирается заново: `session_start`, `session_tree` и `session_compact`.

Причина такой асимметрии — устройство Pi 1.5. Смена набора пересобирает системный промпт. Если обработчик `context` любого расширения меняет окно, Pi сворачивает все системные сообщения в одно, текущее, в начале окна. После сжатия наш обработчик меняет окно всегда: вставляет договорённость. Поэтому снятие инструментов посреди такого окна переписывало бы его начало, и провайдер заново писал бы кэш всего хвоста. Добавление тоже меняет промпт, но случается один раз на цель, сразу после её постановки владельцем.

## Альтернативы

- **Снимать инструменты сразу при закрытии.** Отклонено: после сжатия это меняет начало окна и сбрасывает кэш. Падение поймал дымовой тест на настоящем Pi `test/smoke/compaction-window.test.ts`.
- **Один инструмент с полем «действие» вместо девяти.** Отклонено: это меняет договор каждого вызова и ломает старые формы вызовов в журналах.
- **Оставить всё объявленным.** Отклонено: цена в каждом запросе сессии без цели.

## Последствия

- Сессия без цели несёт одну схему Goal вместо девяти.
- После закрытия цели её инструменты остаются объявленными до следующего старта сессии, смены ветки или сжатия. Вызов в этом промежутке получает обычный отказ «цели нет».
- Модель без цели не может вызвать `get_goal`: такой вызов Pi отклонит как неизвестный инструмент. Смотреть закрытую цель владелец может командами.
- Старые формы вызовов работают: инструменты зарегистрированы, меняется только объявление.

## Не входит

Тексты описаний и правил: их сокращение — отдельная правка без смены договора.

## Проверка

- `test/goal-runtime/goal-tool-loadout.test.ts` — набор без цели, после постановки, после закрытия и после сжатия.
- `test/sdk-runtime-smoke.test.ts` — то же на настоящем SDK Pi.
- `test/smoke/compaction-window.test.ts` — начало окна после сжатия не меняется при закрытии.
