# Цель принадлежит дочерней сессии, а не унаследованной истории

## Контекст

Native fork копирует ветку родителя вместе с записями расширений. В дочернем процессе pi-subagents устанавливает `PI_SUBAGENT_CHILD=1`. Восстановление активной родительской Goal при `session_start` запускает ход раньше поручения ребёнку; запрет только первого продолжения не защищает последующие границы хода и операции над целью.

## Решение

В дочернем процессе с `SessionHeader.parentSession` модули цели читают только собственный участок ветки. Обычная история модели не меняется. Граница хранится записью `goal-compact-child-scope` с полями `sessionId` и `inheritedThrough`: идентификатором последней унаследованной записи либо `null` для пустого префикса. Запись действует только в своей сессии, а не в её следующих форках.

При первом открытии граница определяется по общим идентификаторам записей с родительским журналом. Это сохраняет собственную цель уже работавшего ребёнка, записанную до установки исправления. Родитель читается через `readFileSync` и чистый SDK-парсер `parseSessionEntries`, без открытия записывающего SessionManager. При недоступном или неверном родителе граница не угадывается и восстановление сообщает ошибку. После сохранения границы родитель для повторного открытия не нужен.

Признак дочернего процесса фиксируется при создании экземпляра расширения. Дочерняя сессия может явно завести собственную Goal и продолжать её обычным способом. Интерактивные форки и свежие дочерние сессии без родителя сохраняют прежнее поведение.

## Альтернативы

Отключить продолжение только при старте недостаточно: цель снова вмешается после поручения. Выключить Goals у всех детей мешает собственным целям. Отрезать всё до первого открытия ребёнка теряет уже созданную им цель. Граница по времени зависит от часов; идентификаторы сохраняются при ветвлении. Переписывание родительского журнала и очистка копии уничтожают исторические данные.

## Последствия

Одно чтение родителя нужно только для установки границы. Перезапуск, `/reload` и вложенный fork опираются на сохранённые идентификаторы. Новый формат ничего не меняет в прежних записях целей; чтение старых имён остаётся в прежней точке нормализации.

## Не входит

Изменение автомата цели и сжатия, SDK, pi-subagents, исходных журналов, полномочий ребёнка или способа запуска модели.

## Проверка

Регрессионные тесты проверяют отсутствие родительского автозапуска, сохранение собственного состояния до и после границы, повторное открытие без родителя, вложенный fork, обычную сессию и неизменность исходного файла. Проверки SDK и изолированного TUI дополняются настоящим native fork по тому же пути запуска.
