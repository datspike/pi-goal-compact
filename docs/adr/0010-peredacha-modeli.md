# 0010. Передача работы другой модели после сжатия

## Контекст

Владелец хочет передавать долгую работу другой модели без отправки ей всей старой истории. Передача нужна с целью и без неё. Обычная смена модели сбрасывает эпоху продолжения; согласованная передача должна сохранить законное продолжение, но не отключать защиту от устаревших сообщений.

## Решение

Две команды: `/model-next` выбирает модель для ближайшего успешного сжатия, принимает `status` и `cancel`; `/model-next-now` просит сжатие в ближайшей безопасной точке без обрыва выполняемого инструмента. Обе команды без аргументов открывают пикер, с точным именем выбирают модель, с поисковой строкой открывают пикер с этой строкой. Автодополнение использует тот же нечёткий поиск по имени, идентификатору и провайдеру. Список учитывает scoped models.

Публичный ModelSelectorComponent требует внутренний ModelRuntime; типизированный адаптер реестра расширения SDK не принимает. После проверки владелец выбрал не менять Pi, а максимально повторить поведение на публичных компонентах. Используются Input, SelectList, DynamicBorder и fuzzyFilter Pi. Нового ModelRuntime и настроек моделей нет; приватные поля Pi не читаются.

Решения о продолжении принимает существующее чистое ядро. Сжатие выполняется старой моделью через штатный lifecycle Pi. Только сохранённая запись compaction разрешает переключение. Новая модель, thinking и окно применяются до следующего рабочего запроса. Для автоматического retry используется его собственное продолжение; второго сообщения нет. Для ручной передачи из активной работы используется существующий механизм защищённых билетов. В простое новая задача не запускается. Удержания цели сохраняются.

Намерение и стадия передачи записываются версионированными служебными записями, не попадающими в запрос модели. Они привязаны к текущей сессии и ветке, восстанавливаются после reload/restart. Ручной выбор модели отменяет ожидающую передачу; собственная смена окна — нет. После сбоя продолжение передачи блокируется с понятным сообщением. Уже сохранённое сжатие не повторяется ради повторной смены модели. При восстановлении сверяются фактическая модель и запись сжатия.

## Альтернативы

Буквальное переиспользование штатного пикера проверено и отклонено из-за несовместимого публичного типа. Правку API Pi владелец отклонил в пользу тонкого пикера на общих компонентах. Копия штатного компонента отклонена: дублирует внутреннее устройство и обслуживание. Новый ModelRuntime отклонён: создаёт второй источник настроек и авторизации. Прямой доступ к приватному runtime реестра отклонён. Флаг --now заменён отдельной командой по выбору владельца.

## Последствия

Поведение выбора проверяется на общих компонентах Pi и в настоящем TUI. Старые записи не меняются. Модель по умолчанию для новых сессий и рабочие настройки Pi не меняются. Сжатие сокращает историю, но не убирает системные инструкции, инструменты и свежий хвост и не гарантирует перенос кэша между моделями.

## Не входит

Автоматический выбор дешёвой модели, новые инструменты модели, append-сжатие, публикация, изменение Pi core и рабочего профиля.

## Проверка

Тесты ядра и обвязки проверяют отсутствие продолжения до переключения, отсутствие дублей, ошибки, отмену, свежесть ветки и восстановление. Настоящий SDK без провайдера проверяет порядок сохранения сжатия и смены модели. В настоящем TUI проверены команды и выбор модели; формальная модель задаёт допустимый порядок событий. Реальная передача между моделями проверена в отдельно согласованной видимой Pi-сессии: немедленная передача во время ответа и отложенная после ручного сжатия. Свежий запрос идёт только новой модели; результат исходной задачи проверен исполняемыми тестами.

## Статус

Принято для реализации согласованного поведения.
