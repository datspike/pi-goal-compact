# 0021. Восстановление принадлежит ходу, а не цели

## Контекст

Решение [0020](0020-povtor-na-granitse-pi.md) продолжает тот же ход после штатного повтора Pi, но включает этот путь только у активной цели. Обычный чат и дочерний ход тоже должны переживать временный отказ провайдера без перезапуска работы. На Pi 1.5.2 тестовое расширение запросило такое продолжение в дочерней сессии после двух HTTP `503`, без PiRetry. Свежий запуск, fork и фоновый запуск доставили по одному итогу.

## Решение

У хода один владелец дополнительного восстановления. Он использует границу `agent_before_settle` после штатных попыток, сохраняет прежние результаты и получает ограниченное право на повтор той же модели по подтверждённой временной ошибке. Автоматическая смена модели разрешена только для пары `openai/gpt-6.2-astra` → `openai/gpt-6.2-sol`. Пауза, ожидание ответа и разрешение продолжать цель остаются правилами цели, а не условиями для обычного чата и ребёнка без своей цели.

Право продолжать связано с текущим ходом, сессией и веткой. Отмена, истечение срока задания ребёнка, новый ввод и ручная смена модели не дают перенести его на другой ход. Длинное ожидание разрешено только после проверки пути отмены в этом режиме. Ошибка уже после перехода не открывает новое окно. Если PiRetry загружен в сессии, новый механизм не добавляет второй повтор.

В дочернем Pi ожидание на `agent_before_settle` раньше могло попасть под защиту `pi-subagents` от зависания при завершении. Встроенный запуск сообщает дочернему расширению о возможности ожидания через `pi-subagents:provider-recovery`. Этот договор приостанавливает только очистку при завершении хода, передаёт сигнал родительской отмены и проверяет ограничения модели для запуска. Он не продлевает срок задания. Без ответа на событие в дочерней сессии дополнительный повтор не включается.

## Альтернативы

Три независимых планировщика пришлось бы синхронно исправлять при каждой гонке. Перезапуск ребёнка или новая реплика для автоматического повтора могут повторно запустить инструмент. Удаление всех проверок цели снимет её ручную паузу и прочие ограничения. Ни один из этих путей не нужен для общего повтора.

## Последствия

Правило срока и перехода проверяется отдельно от оболочки. Для обычного чата и цели нужны проверки ввода и Esc; для ребёнка — путь отмены из родителя и один итог. Закрытая, приостановленная или унаследованная цель не становится активной только из-за попытки восстановления.

## Не входит

Изменение рабочего профиля или перенос скрытых сообщений PiRetry для автоматического повтора.

Для явного повтора из простоя команда `/retry-request` действует только на последнюю безопасную ошибку обычного чата в той же сессии, ветке и модели. Pi 1.5.2 начинает такой ход через `sendMessage`; команда оставляет видимую отметку. `context_with_system` убирает отметку и неудавшийся ответ из запроса без пересборки системного начала. После ответа `context_edit` исключает отметку и ошибку из следующих запросов. Нового окна автоматического восстановления эта команда не открывает.

## Проверка

Правило срока проверяется на Astra, Sol и другой модели: разрешён только повтор текущей модели, а при исчерпании срока — остановка или единственный разрешённый переход. На настоящем Pi в каждом режиме подтверждаем полезное продолжение после штатных попыток, сохранение результатов и отмену без нового запроса.

## Статус

Принято.
