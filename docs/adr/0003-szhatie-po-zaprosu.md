# 0003. Сжатие по запросу агента идёт через `ctx.compact`, а не черновиком записи

## Контекст

Инструмент `checkpoint_compact_continue` сохраняет контрольную точку, сжимает окно и продолжает работу. Граница `agent_before_settle` позволяет дописать запись `compaction` сразу вместе с продолжением — сжатие и продолжение стали бы одним шагом без очереди.

Но такое сжатие не вызывает событий `session_before_compact` и `session_compact`. На них слушают соседи: Recall сбрасывает память перед сжатием (`src/handlers/session-flush.ts`) и подтягивает контекст после него (`src/personalization.ts`).

## Решение

Сжатие по запросу агента запускается из `agent_settled` через `ctx.compact`, как прежде: события сжатия видят все расширения. Продолжение после него — билет (решение 0002), годный и без цели, и после закрытия цели, но не при ожидании владельца и не на паузе.

Сводку для любого сжатия — по порогу, переполнению, команде или запросу агента — пишет расширение в `session_before_compact`, на обоих языках (требование Т11.3).

## Альтернативы

- **Черновик записи `compaction` на границе.** Отклонено: соседи теряют события сжатия.

## Последствия

- После сжатия по запросу агента остаётся один путь из простоя, и он покрыт сверкой билета.
- Сжатие по порогу и переполнению Pi делает внутри прогона и сам повторяет запрос; продолжение после них решается на обычной границе.

## Не входит

Дописывающее сжатие (append) — отдельный последний срез; на этот выбор оно не влияет.

## Проверка

Модель 1: действия `RequestCheckpoint`, `CompactDone`, `DeliverIdle`; поломка `noGoalCheckOnTicket` показывает, что без сверки билет после сжатия ломает ожидание владельца. Тест обвязки проверяет, что `session_before_compact` вызывается при сжатии по запросу агента.

## Статус

Принято.
