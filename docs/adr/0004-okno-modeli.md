# 0004. Окно модели собирается при каждом запросе из долговечного состояния

## Контекст

После сжатия модель видит сводку, которую сама же написала. Замысел владельца из сводки постепенно уходит: в одной из долгих сессий требование о русском стиле пропало из раздела «Цель» со второго сжатия. Решения Д2, Д6, Д7 требуют, чтобы договорённость стояла в начале окна ровно одной копией, а у каждого факта был один хозяин.

## Решение

Хук `context` при каждом запросе к модели собирает начало окна:

1. сводка последнего сжатия; при незакрытой цели её раздел «Цель» вырезается;
2. сразу за ней — договорённость последней редакции из состояния цели; у цели, созданной старой парой, — её прежний договор в пределах размера;
3. без цели — последние реплики владельца дословно, около 1500 знаков (решение Р4).

В журнал собранное не пишется: источник — записи цели и сводки, а сборка повторяется. Текст в начале окна меняется только при новой редакции договорённости или новом сжатии, поэтому кэш провайдера не сбрасывается на каждом запросе.

Сборщик не держит копию договорённости между запросами.

## Альтернативы

- **Писать договорённость в журнал отдельным сообщением после каждого сжатия.** Отклонено: появляются вторая копия при новой редакции и вопрос, какая из них действует.
- **Просить модель сохранять договорённость в сводке.** Отклонено: именно пересказ моделью и терял требования.

## Последствия

- Договорённость видна в каждом окне, а не только после продолжения.
- Код сборки окна один для русского и английского вариантов.
- Каждая доработка Д2, Д6, Д7 выключается настройкой (Д9).

## Не входит

Как модель пишет договорённость — решение Д1 и требования раздела 3.

## Проверка

Модель `formal/Agreement.tla`, свойство П7; поломки `noStrip` и `staleCache`. Проверка на случайных входах по настоящему разбору сводки (В1).

## Статус

Принято. Что стоит в начале окна между сжатиями, уточнено решением [0012](0012-nachalo-okna-na-moment-szhatiya.md).
