# 0009. Одна настройка языка, русский текст — источник истины

## Контекст

Расширение говорит с двумя читателями: с владельцем (лента, нижняя строка, `GOAL.md`, команды) и с моделью (описания инструментов, правила, продолжение, ошибки инструментов). Прежние расширения писали их на разных языках: сводку — по-русски, правила и ошибки — по-английски. Нужен один выбор языка на всё, включая английский вариант для публикации.

## Решение

Язык читается из настроек Pi один раз при загрузке — ключ `contextCompaction.language`, для совместимости `summaryLanguage` — и хранится в модуле `src/language.ts`. Текст выбирается вызовом `say(рус, англ)`: русская строка — источник истины, английская — её перевод. Правила для модели, подобранные прогонами на английском, переведены на русский без изменения смысла.

Поскольку язык известен только после загрузки, тексты на уровне модуля сделаны функциями, а не константами. Английскую сводку тоже пишет расширение, а не Pi.

Что намеренно остаётся английским:

- внутренние ошибки целостности журнала и блокировки документа — их видит разработчик, а не владелец;
- причины пауз, которые пишутся в журнал и сравниваются по тексту;
- системный промпт модели-сводчика — язык сводки задаёт инструкция.

## Альтернативы

- **Передавать язык параметром во все функции вывода.** Отклонено: правка сотен сигнатур ради значения, которое не меняется до `/reload`.
- **Принимать «продолжи» и «continue» при любом языке.** Отклонено: слово возобновления точное и только на языке расширения, иначе ломается проверка, что прочие реплики толкует модель через `resume_goal`.
- **Оставить правила для модели английскими в обоих вариантах.** Отклонено требованием Т11.1: одна настройка управляет всем, что читает модель.

## Последствия

- Журнал, записанный при другом языке, остаётся читаемым: кадры продолжения узнаются на обоих языках, тексты исправлений принимаются на обоих.
- В английском варианте русские правила языковой проверки (смешение языков, шаблонная лексика) не действуют; правила структуры и следов чат-бота остаются.
- Тест, который меняет язык, обязан вернуть прежний: язык — общее состояние модуля. В тестовой обвязке язык задаётся на весь файл через `useHarnessLanguage`; перенесённые из `pi-codex-goal` проверки записи и восстановления идут на английском и тем самым проверяют английский вариант.
- Русский перевод правил поведенчески не проверен прогонами; это задача модельной проверки.

## Не входит

Язык документации и комментариев в коде — он задан правилами репозитория.

## Проверка
