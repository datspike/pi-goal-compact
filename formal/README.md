# Формальная проверка

Три небольшие модели автомата расширения на TLA+. Они пишутся раньше кода ядра и служат его чертежом (решение [0008](../docs/adr/0008-formalnaya-proverka.md)).

```sh
npm run check:formal
```

Команда скачивает TLC v1.8.0 в `formal/.cache/`, сверяет контрольную сумму и прогоняет каждую модель дважды: исправную — она обязана пройти — и с каждой намеренной поломкой — та обязана нарушить своё свойство. Нужна Java.

## Модели

**`Continuation.tla`** — продолжение и удержание.

| Свойство | Что обещаем | Что будет, если нарушить |
|---|---|---|
| П1 | В очереди не больше одного свежего билета продолжения | Двойная работа и двойной расход |
| П2 | Пока цель ждёт владельца или стоит на паузе, работа без владельца не начинается | Агент решает за владельца |
| П3 | Закрытая или очищенная цель не оживает | Работа после того, как владелец её остановил |
| П4 | Пока исход записи неизвестен, работа без владельца не начинается | Расширение действует по состоянию, которого может не быть в журнале |
| П5 | Устаревший билет не запускает работу | Чужое продолжение в другой ветке разговора |
| П6 | Активная цель в простое не стоит молча | Работа тихо останавливается |

**`Agreement.tla`** — договорённость в окне и закрытие.

| Свойство | Что обещаем | Что будет, если нарушить |
|---|---|---|
| П7 | После сжатия при незакрытой цели в окне одна договорённость последней редакции | Модель работает без замысла владельца или по устаревшему |
| П8 | Цель закрывается только после возврата договорённости и отчёта `verifying` для текущих версий | Закрытие по устаревшей проверке |
| П9 | Договорённость меняется только в прогоне владельца | Агент сам переписывает цель |

## Границы перебора

Модель 1: до четырёх смен эпохи, до трёх билетов в очереди, один сабагент, одна контрольная точка — 5781 состояние. Модель 2: до трёх редакций договорённости и версий плана — 13 074 состояния. Чистый прогон доказывает свойства только в этих границах.

## Как читать падение

Скрипт печатает цепочку действий контрпримера. Каждое падение исправной модели получает один из трёх ярлыков: неверно свойство, неверна модель, настоящий дефект замысла. Свойство не ослабляется ради зелёного прогона.

## Покрытие

Неделимый шаг модели — обработчик события Pi до первого `await`. Какие файлы ядра повторяют какие действия модели, записывается здесь, когда ядро появится; изменение этих файлов требует пересмотра модели в том же коммите.

## Передача модели

`ModelTransfer.tla` проверяет сохранение сжатия до смены модели (П10), применение модели до рабочего запроса (П11), отсутствие двойного продолжения при повторе Pi (П12) и сохранение удержания цели (П13). Исправный конечный автомат перебирает 36 состояний; каждая из четырёх намеренных поломок нарушает своё свойство.

Формальная модель проверяет выбранный порядок событий, а не размер запроса и не поведение SDK. Связь с реализацией: события передачи в `src/core/step.ts`, ожидание `afterSaved` в `src/shell/compaction.ts` и операции Pi в `src/shell/model-transfer.ts`. Порядок настоящего автоматического повтора дополнительно проверяет `test/smoke/model-transfer.test.ts` на локальном транспорте без сети.
