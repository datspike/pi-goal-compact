# pi-goal-compact

Расширение Pi: ведёт долгую работу к цели через много окон контекста и сжимает контекст так, чтобы замысел владельца не терялся. Заменяет пару `pi-codex-goal` и `context-compaction`. Точка сборки — `src/index.ts`.

## С чего начать

- Что расширение обещает владельцу и модели — `README.md`. Он источник истины о поведении; `README.en.md` его повторяет.
- Почему оно устроено так — решения в `docs/adr/`, порядок их оформления в `docs/adr/README.md`.
- Как идёт работа над задачей — `docs/workflows.md`.
- Если есть `AGENTS.local.md`, прочитай его перед выбором задачи, после сжатия контекста и после смены worktree. Правила в Git обязаны работать и без него.

## Язык

Документы, решения, комментарии в коде, названия тестов и тексты для владельца пишутся по-русски, простыми словами, без канцелярита и лишних англицизмов. Идентификаторы в коде английские. Команды, пути, поля API и значения форматов не переводятся и не искажаются.

Тексты, которые читает модель, существуют в двух вариантах — русском и английском. Русский основной: меняешь его — меняй и английский в той же работе.

## Границы

- Решение, которое меняет договор инструментов, записи журнала сессии, устройство слоёв или зависимости, сначала оформляется в `docs/adr/`. Обычной правке решение не нужно.
- У каждого факта, который видит модель, один хозяин. Прежде чем добавить текст в окно модели, найди, кто уже несёт этот факт.
- Расширение проверяет порядок событий и структуру данных, а не правду слов агента.
- Системный промпт и уже отправленные сообщения не меняются: это сбрасывает кэш провайдера.
- Прежние записи журнала и каталоги `pi-codex-goal` и `context-compaction` остаются читаемыми. Смена формата требует решения и проверки на старой сессии.

## Публичное и локальное

В Git и в npm-пакет не попадают `.task_files/`, `.runtime/`, `.pi/`, `AGENTS.local.md`, записи сессий, настройки провайдеров, личные пути и секреты. Планы и сырые результаты прогонов нельзя сначала закоммитить, а потом удалить: они останутся в истории. Проверка — `npm run check:public`.

Примеры для тестов и документов готовятся обезличенными. Реплики из настоящих сессий в репозиторий не переносятся.

## Проверки

| Команда | Что проверяет |
|---|---|
| `npm run verify` | Всё обязательное одной командой: типы, слои, неиспользуемый код, тесты, приватные границы, модели TLA+ |
| `npm run typecheck` | Типы кода, тестов и скриптов |
| `npm test` | Тесты без обращения к модели |
| `npm run lint:arch` | Слои и циклы импортов |
| `npm run lint:dead` | Неиспользуемый код и зависимости |
| `npm run check:public` | Приватные границы дерева и состава пакета |
| `npm run check:formal` | Модели TLA+ в `formal/` и намеренные поломки; нужна Java |
| `npm run lint:style`, `npm run lint:dup` | Сигналы читаемости и повторы; в `verify` не входят |

Списков известных нарушений нет. Нарушение слоёв или неиспользуемый код исправляются, а не заносятся в исключения. Предупреждение о размере или сложности — повод прочитать код, а не дробить его механически.

Перед изменением поведения найди ближайшую реализацию, её вызывающие места и тесты. После изменения запусти адресные тесты и `npm run verify`. Поведение, видимое владельцу, проверяется на пользовательском пути, а не только внутренним вызовом. Модельные прогоны требуют отдельно согласованного бюджета.

## Git

Законченную и проверенную работу сохраняй связными локальными коммитами в формате Conventional Commits: `type(scope): краткое описание`. Перед коммитом посмотри состав: чужие изменения, секреты и временные файлы в него не входят. Push, запросы на слияние и публикация пакета требуют прямого поручения.
